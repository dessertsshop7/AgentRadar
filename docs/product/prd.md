# AgentRadar 产品定义

状态：P01 产品设计保留；P02 数据契约于 2026-10-18 按 V2.0 更新（Asia/Singapore）。产品判断均未经过用户访谈或市场验证。
本文件负责目标、规则、故事和下一阶段输入；画像、旅程、优先级、路由、设计和指标分别见同目录专项文档。

## 定位与用户选择

AgentRadar 帮助用户完成：发现 AI 工具 → 理解工具 → 判断适配 → 尝试应用 → 反馈结果。
它把项目原始资料、中文解释和适用条件放在一起，让工具选择有依据、尝试过程可回顾。
当前没有证据证明用户愿意持续使用或付费，也没有访谈、留存、安装成功率等真实运营数据。

| 优先级 | 用户 | 选择依据（产品假设） | 需要验证 |
| --- | --- | --- | --- |
| 首要 | 有具体任务的产品/运营人员 | 需求较具体，可以围绕文档整理、内容运营等任务观察完整闭环 | 是否愿意补充约束、尝试候选并反馈，而不只是浏览 |
| 次要 | 不熟悉 GitHub 的 AI 初学者 | 共享发现、中文解释和上手条件；需要更少术语 | 是否能理解来源、局限和部署门槛 |
| 后续重点 | 技术支持人员 | 部署、诊断和知识沉淀价值明确，但依赖可用工具、环境信息和权限治理 | 是否有重复故障与团队协作需求 |

核心问题：工具介绍难懂、热度与适配混淆、环境条件不明确、外链点击后结果不可见。
价值主张：用可追溯解释和明确限制，支持一次可判断、可尝试、可反馈的选择。

## 当前能力与首版目标

- P00 已实现：真实 API/PostgreSQL 健康检查、迁移、错误与日志、容器、自动检查基础。
- P01 原型：发现/详情/固定选型演示；所有工具为虚构案例，输入只在当前页面内存中处理。
- MVP 目标：用真实且经过审核的工具信息，完成理解、规则选型、试用指引及自报结果的闭环。
- 增强版：更丰富的诊断、趋势、收藏、场景方案库与运营后台；模型辅助能力必须有引用、失败降级和评估。
- 企业版：组织、权限、工具资产、审批、支持工单和审计。
- 暂不考虑：执行外部仓库任意命令、自动替用户部署、双向同步私人数据库、工具交易市场。

MVP 范围和依赖以 [功能优先级](feature-priority.md) 的 F01–F16 为准；当前 P02 以用户 Prompt 为准，
后续阶段按 V2.0 规划，仍须用户明确授权执行。

## 成功标准与范围

P01 的实际验收是三页流程可操作、演示边界可见、键盘和三个宽度可用、工程状态入口仍有效；
详见本文件末尾原型条件。以下是未来 MVP 验收条件，不代表已经实现：

1. F01/F02：用户按场景和门槛查找工具，能读到中文解释、来源与未知项；没有符合条件的条目时给出恢复路径。
2. F03：用户提交约束后看到规则依据、排除原因和待核实项；无匹配时不硬凑推荐。
3. F04：试用指引明确环境、依赖、费用未知项和可验证步骤；不自动执行命令。
4. F05：用户可以分别反馈尝试与结果，系统能区分自报成功和有证据的验证。
5. F06/F07：每条已发布内容可审查，核心漏斗可在用户同意后用实际事件复算。

不设虚构增长目标。建议用小规模邀请测评检验任务理解与闭环意愿，样本数、时间和达标阈值由实际招募计划确定。

## 关键规则

- 工具的热度、适配、可信度分开表达；未知费用/许可证/系统支持写“待核实”，不能推断为免费或可商用。
- 原始资料、人工解释、AI 生成与演示内容必须记录来源类型；AI 内容未经审核不能等同官方说明。
- 外链点击只证明点击；安装、尝试、应用成功分别记录；结果自报不当作平台验证。
- 不记录无依据的采集时间、推荐置信度、实时排行或用户数量。
- 搜索、筛选使用 URL 状态；无结果保留条件并允许清除；详情缺失给出返回发现入口。
- 当前 P01 没有写入、模型、鉴权、分析 SDK 或后端业务请求；刷新助手后需求和结果不保留。
- 页面可见的演示规则仅使用场景与技术条件；文本只用于展示上下文，不做语义理解。
- 后续收藏/后台/组织资源必须先确定身份、权限与数据隔离方案，不能通过隐藏按钮代替鉴权。

## P01 原型实际验收条件

- `/` 进入 `/discover`；搜索名称、摘要、标签；组合场景/门槛，URL 保留条件；空结果可清除。
- 六个虚构工具集中在 `apps/web/public/demo/catalog.json`；三页均可见“演示数据”。
- 详情列出适用、不适用、配置门槛、限制、概念性步骤和来源边界；没有虚假的仓库外链。
- 详情可带工具上下文进入助手；场景 + 技术条件选择固定候选；非空白需求至少 10 字、最多 500 字；校验失败移除上次方案，避免旧结果冒充本次结果。
- 助手清楚显示“演示交互，未连接模型”和规则；输入原文不参加语义分析、不持久化、不提交到业务服务。
- 区分目录加载、目录为空、筛选无结果、读取失败（可重试）与不存在的详情（可返回）。
- 375/768/1440px 布局可用；键盘能搜索、打开详情、提交需求，焦点可见；`/status` 仍调用真实 API。
- 无 SDK/模型/采集/用户/收藏/后台/企业实现，无业务迁移；静态检查、类型检查、构建和针对性浏览器验证有实际记录。

字段、稳定 ID、来源、未知项、版本/发布状态和约束见 [数据字典](../architecture/p02-data-dictionary.md)。
