# AgentRadar 产品定义

状态：P01 设计基线，2026-10-17（Asia/Singapore）。产品判断均未经过用户访谈或市场验证。
本文件负责目标、规则、故事和下一阶段输入；画像、旅程、优先级、路由、设计和指标分别见同目录专项文档。

## 定位与用户选择

AgentRadar 帮助用户完成：发现 AI 工具 → 理解工具 → 判断适配 → 尝试应用 → 反馈结果。
它把项目原始资料、中文解释和适用条件放在一起，让工具选择有依据、尝试过程可回顾。
当前没有证据证明用户愿意持续使用或付费，也没有访谈、留存、安装成功率等真实运营数据。

| 优先级 | 用户 | 选择依据（产品假设） | 需要验证 |
| --- | --- | --- | --- |
| 首要 | 有具体任务的产品/运营人员 | 需求较具体，可以围绕文档整理、内容运营等任务观察完整闭环 | 是否愿意补充约束、尝试候选并反馈，而不只是浏览 |
| 次要 | 不熟悉 GitHub 的 AI 初学者 | 共享发现、中文解释和上手条件；需要更少术语 | 是否能理解来源、局限和部署门槛 |
| 后续重点 | 技术支持人员 | 部署、诊断和知识沉淀价值明确，但依赖可用工具、环境信息和权限治理 | 是否有重复故障与团队协作需求 |

核心问题：工具介绍难懂、热度与适配混淆、环境条件不明确、外链点击后结果不可见。
价值主张：用可追溯解释和明确限制，支持一次可判断、可尝试、可反馈的选择。

## 当前能力与首版目标

- P00 已实现：真实 API/PostgreSQL 健康检查、迁移、错误与日志、容器、自动检查基础。
- P01 原型：发现/详情/固定选型演示；所有工具为虚构案例，输入只在当前页面内存中处理。
- MVP 目标：用真实且经过审核的工具信息，完成理解、规则选型、试用指引及自报结果的闭环。
- 增强版：更丰富的诊断、趋势、收藏、场景方案库与运营后台；模型辅助能力必须有引用、失败降级和评估。
- 企业版：组织、权限、工具资产、审批、支持工单和审计。
- 暂不考虑：执行外部仓库任意命令、自动替用户部署、双向同步私人数据库、工具交易市场。

MVP 范围和依赖以 [功能优先级](feature-priority.md) 的 F01–F16 为准；阶段号只有 P00/P01 已确定，
“P02 候选”是建议输入，须以下一阶段 Prompt 为准，其他阶段号不预先承诺。

## 成功标准与范围

P01 的实际验收是三页流程可操作、演示边界可见、键盘和三个宽度可用、工程状态入口仍有效；
详见本文件末尾原型条件。以下是未来 MVP 验收条件，不代表已经实现：

1. F01/F02：用户按场景和门槛查找工具，能读到中文解释、来源与未知项；没有符合条件的条目时给出恢复路径。
2. F03：用户提交约束后看到规则依据、排除原因和待核实项；无匹配时不硬凑推荐。
3. F04：试用指引明确环境、依赖、费用未知项和可验证步骤；不自动执行命令。
4. F05：用户可以分别反馈尝试与结果，系统能区分自报成功和有证据的验证。
5. F06/F07：每条已发布内容可审查，核心漏斗可在用户同意后用实际事件复算。

不设虚构增长目标。建议用小规模邀请测评检验任务理解与闭环意愿，样本数、时间和达标阈值由实际招募计划确定。

## 关键规则

- 工具的热度、适配、可信度分开表达；未知费用/许可证/系统支持写“待核实”，不能推断为免费或可商用。
- 原始资料、人工解释、AI 生成与演示内容必须记录来源类型；AI 内容未经审核不能等同官方说明。
- 外链点击只证明点击；安装、尝试、应用成功分别记录；结果自报不当作平台验证。
- 不记录无依据的采集时间、推荐置信度、实时排行或用户数量。
- 搜索、筛选使用 URL 状态；无结果保留条件并允许清除；详情缺失给出返回发现入口。
- 当前 P01 没有写入、模型、鉴权、分析 SDK 或后端业务请求；刷新助手后需求和结果不保留。
- 页面可见的演示规则仅使用场景与技术条件；文本只用于展示上下文，不做语义理解。
- 后续收藏/后台/组织资源必须先确定身份、权限与数据隔离方案，不能通过隐藏按钮代替鉴权。

## P01 原型实际验收条件

- `/` 进入 `/discover`；搜索名称、摘要、标签；组合场景/门槛，URL 保留条件；空结果可清除。
- 六个虚构工具集中在 `apps/web/public/demo/catalog.json`；三页均可见“演示数据”。
- 详情列出适用、不适用、配置门槛、限制、概念性步骤和来源边界；没有虚假的仓库外链。
- 详情可带工具上下文进入助手；场景 + 技术条件选择固定候选；非空白需求至少 10 字、最多 500 字；校验失败移除上次方案，避免旧结果冒充本次结果。
- 助手清楚显示“演示交互，未连接模型”和规则；输入原文不参加语义分析、不持久化、不提交到业务服务。
- 区分目录加载、目录为空、筛选无结果、读取失败（可重试）与不存在的详情（可返回）。
- 375/768/1440px 布局可用；键盘能搜索、打开详情、提交需求，焦点可见；`/status` 仍调用真实 API。
- 无 SDK/模型/采集/用户/收藏/后台/企业实现，无业务迁移；静态检查、类型检查、构建和针对性浏览器验证有实际记录。

## P02 候选：最小数据输入

建议先把“真实人工审核目录 + 查询”接通，保留模块化单体及 `/api/v1`；不一次建立助手、反馈、诊断和组织模型。
下面是拆解草案，不是已经承诺或已创建的表/API；P02 开始前须结合实际样本与 Prompt 确认。

| 实体 | 最小字段及约束 | 来源与目的 |
| --- | --- | --- |
| Tool | `id` UUID；`slug` 唯一稳定；`name`；`kind`（app/agent/skill/mcp/library）；`category`；`tags`；`difficulty`（beginner/visual/developer）；`status`（draft/published/withdrawn）；`current_content_version_id` | 经维护者审查的真实项目；对外只查询 published。类别和标签先用受控值，不提前建复杂分类系统 |
| SourceReference | `id`；`tool_id`；规范 `repository_url`；`repository_full_name`；`revision` 可空；`locator`（README 段落/文档路径）；`checked_at` 为实际人工核对时间；`license_spdx` 可空；`verification_note` | 官方仓库/文档，记录事实依据；未知版本、许可证要有缺失说明；不为了造数据填写时间 |
| ToolContentVersion | `id`；`tool_id`；递增 `version`；`summary_zh`；`use_cases`；`not_for`；`requirements`；`limitations`；`installation_note`；`pricing_note`；`source_reference_ids`；`origin`；`review_status`；`reviewed_at` 可空；`created_at` | P02 建议人工编写并审核（origin=human）；原始摘录/AI 生成/演示必须另标，不把 P01 虚构案例迁入发布库 |

费用、兼容系统与许可证未知时使用明确的 unknown/待核实语义；不要让空值变成“免费/支持所有系统”。
更新内容创建新版本，在事务内切换当前版本；表结构使用新增 Alembic 迁移，不改 P00 空基线。

| 候选接口 | 输入/输出与行为 |
| --- | --- |
| `GET /api/v1/tools` | `q` ≤100 字；`category`、`difficulty` 受控；`page` ≥1；`page_size` 1–50；返回 `items,total,page,page_size,request_id`。默认 slug 稳定排序，不称趋势/推荐排名；中文匹配规则和 AND 筛选需真实 PostgreSQL 验证 |
| `GET /api/v1/tools/{slug}` | 返回详情、内容版本、来源与审核信息、未知项及 `request_id`；缺失/未发布统一 404，不泄露草稿 |
| 受控人工导入入口（建议项目脚本） | 校验规范 URL、枚举、slug 唯一、必需来源与发布条件；幂等更新、事务和错误日志。P02 不依赖开放写 API 或未实现的管理权限 |

前端 URL 使用 `level`，数据/API 使用 `difficulty`，读取适配入口显式转换；`q`/`category` 保持同义。
列表项至少提供 `id,slug,name,kind,category,tags,difficulty,summary_zh,content_version_id,origin`；详情追加条件、限制、来源与审核记录。
空结果为 200 + `items=[]`；非法参数走统一 422，缺失详情走统一 404；错误、请求 ID 和日志复用 P00 契约。
P02 用真实 DTO 和页面适配替换演示读取入口，不通过改标签把虚构条目当作真实数据。
中文分词必须实测，不能把英文全文检索配置当成中文可用证据；小规模必要时评估参数化 ILIKE 回退并记录限制。
来源 URL 不意味着允许后端任意抓取或执行 README 命令；未来抓取需单独设计网络边界、超时、限流和失败处理。

更后阶段单独输入：需求/候选规则与版本（助手）、尝试/结果/证据（反馈）、事件与同意（分析）、
环境/问题/知识条目（支持）、用户/角色（后台/收藏）、组织/资产/审计（企业）。这些均不属于 P02 最小目录。
