# 功能优先级与交付边界

2026-10-17，P01 假设规划。P0=正确性/闭环前置，P1=首个真实目录后补齐，P2=后续价值。
MVP 是产品版本范围，不等于 P01，也不等于 P02；后续阶段号由用户指定。

| ID / 范围 | 用户价值、任务/页面 | 依赖 | 优先级与理由 | 未来验收/成功标准 | 计划阶段 |

暂不实现：任意仓库代码执行、自动代部署、跨私人数据库双向同步、社交动态/交易市场、
无来源的综合评分、以外链点击计安装、无限制日志/密钥收集。它们缺少当前任务依据或会显著扩大安全与运维边界。

首轮建议顺序：F06 + F01/F02 → F03/F04 → F05/F07。此顺序是待验证的交付建议，不授权自动进入下一阶段。
P01 实际能力、路由与验收详见 PRD 和信息架构；每项 MVP 已对应故事、页面/维护入口和成功标准。
