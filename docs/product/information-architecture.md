P02 初期可通过受控维护流程审核内容，不把运营后台和用户系统作为目录的隐性前置。

## 核心路径与 URL 约定

```text
/ → /discover?q=关键词&category=knowledge&level=beginner
    → /tools/knowledge-base
    → /assistant?tool=knowledge-base
    → 本页固定结果 → 候选详情 / 修改需求
任意可用页 → /status → /api/v1/health → 真实 PostgreSQL
```

- `q` 搜索名称、摘要、标签及分类关键词，忽略大小写；多个筛选条件按 AND 合并。
- `category` 使用 knowledge/operations/support，`level` 使用 beginner/visual/developer。
- URL 条件可刷新、分享和浏览器返回；输入尚未提交前不会改变结果。未知筛选值提示清除，不静默扩大查询。
- 工具上下文来自 `tool` 参数；未知工具提示重新选择，不伪造带入的工具。
- 助手任务和结果只在页面内存，不写 URL（避免需求原文进入链接/历史）、不持久化；修改需求保留当前输入。
- 卡片标题是详情链接，按钮用于提交/重试；没有可用目标的功能只以说明文字呈现。

## 原型页面结构

- 统一外壳：跳到内容 → 品牌/导航/当前页 → 可见演示说明（产品三页）→ 主要内容 → 阶段边界页脚。
- 发现：任务标题 + 助手入口 → 搜索 → 左侧场景/门槛（小屏置上）→ 结果数/卡片或状态面板。
- 详情：返回发现 → 类型/门槛 → 用途 → 适用/不适用 → 概念能力和试用前检查 → 来源边界；旁栏进入助手。
- 助手：边界说明/当前工具 → 需求表单 → 固定映射结果/限制 → 概念尝试清单；反馈提示“规划中”，不可提交。
- 工程：原 P00 健康面板，保留真实 HTTP 状态、时间、请求 ID 和重新检查。
